## 1. 平台定位与目标

### 1.1 平台定位

**江南古典园林空间知识图谱可视化平台**

本平台所承载的数据库不是普通知识图谱，而是**具有空间语义的园林知识图谱**：每个实体带平面坐标（x/y），每条空间关系带方向、距离与空间语义描述（相邻类型、中介、接触类型）。平台围绕这一特性设计。

### 1.2 平台目标

平台突出三大要素：**知识图谱 + 空间信息 + 园林数字化展示**。

1. **知识图谱**：以图结构展示园林实体（建筑、山石、池沼、花木等）及其语义关联，支持浏览、搜索、逐层探索；
2. **空间信息**：利用实体 x/y 测绘坐标还原园林平面格局；展示空间关系的方向、距离、相邻类型、中介等语义；利用"建筑环线 + 环线序号"复原园林游览动线；
3. **园林数字化展示**：为江南古典园林文化遗产的数字展示、研究与科普提供直观工具，并为后续大语言模型辅助查询提供数据基础。

## 2. 数据基础：空间语义知识图谱

> 详见 `database/schema.md`（对本地 Neo4j 的实连分析）。

### 2.1 核心原则：不预设任何实体分类

平台**不假设**任何标签、关系类型或属性字段。所有 Schema 信息——标签（`CALL db.labels()`）、关系类型（`CALL db.relationshipTypes()`）、属性键（`keys(n)` / `keys(r)`）——一律在运行时从 Neo4j **动态读取**，前端图例、配色、筛选、详情面板全部随之动态生成。数据库中未来新增标签/关系/属性，平台无需改代码即可适配。

### 2.2 空间语义数据特征（当前 `canglangting` 库实测）

| 数据层 | 特征 | 平台利用方式 |
|---|---|---|
| 实体空间位置 | 每个要素节点带 `x`/`y` 平面坐标（米制，`建筑0-1` 入口为原点）及等价的 `极径_m`/`极角_度` | **空间布局模式**（园林平面图） |
| 空间关系语义 | `相邻` 边带 `相邻类型`（建筑环线/可看/对景）、`中介`（园路/水面/山径/植物…）、`方向`（中文十六方位）、`距离_m`、`极角_度`；`相接` 边带 `接触类型`（临水/在山上/在山边）等 | 关系悬浮提示、关系属性面板、关系过滤 |
| 游线数据 | `相邻(相邻类型=建筑环线)` 边带 `环线序号`（1–14，构成建筑游览闭环） | **游线分析模块**：按序号排序还原游览动线 |
| 多库一园 | 每个园林是独立数据库（当前仅 `canglangting` 已加载，另有 21 个 dump 待加载）；单园约 29 节点 / 76 边 | 后端多库路由 + 前端园林切换器；22 园全量约 640 节点，属小规模图谱 |

### 2.3 空间语义三层模型

数据库的空间语义可归纳为三个层次，平台功能围绕这三层展开：

```
┌─ 位置层：实体在哪里
│   节点属性 x / y（米制平面坐标，入口原点；极径_m/极角_度为等价冗余）
│   → 空间布局模式（园林平面图）
│
├─ 关系层：实体之间如何联系（空间语义属性，附着在边上）
│   相邻：相邻类型（可看 16 / 建筑环线 14 / 对景 4）+ 中介（园路、水面、山径、
│         竹林、桂树…共 18 种）+ 方向（中文十六方位，15 种取值）+ 距离_m
│   相接：接触类型（在山边 8 / 临水 4 / 在山上 2）+ 方向 + 距离_m
│   属于：关系（园内）——要素挂接园林根节点
│   → 空间关系展示（tooltip/详情面板/关系过滤）、空间条件查询
│
└─ 游线层：如何游览（环线序号附着在"建筑环线"边上）
    14 条带环线序号的有向边构成闭环游览线：大门 / 入口 → 面水轩 → 观鱼处 →
    沧浪亭 → 明道堂 → 清香馆 → 五百名贤祠 → 仰止亭 → 翠玲珑 → 看山楼 →
    瑶华境界 → 御碑亭 → 厕所 → 沧浪胜迹坊 → 大门 / 入口（总长 487.7m）
    → 游线分析模块（逐步动画展示游览动线）
```

> 三层数据的键名（`x`/`y`、`相邻类型`、`中介`、`方向`、`距离_m`、`环线序号` 等）为当前 schema 实测所得；接口实现仍按"属性存在才返回"原则做动态处理，其他园林库缺层时功能优雅降级。

## 3. 总体架构

```
浏览器（Vue 3 + Element Plus + ECharts）
        │  HTTP REST（/api/*，JSON）
        ▼
FastAPI 后端（Python 3.10+，neo4j-driver）
   ├── 查询构造层（参数化 Cypher + 动态标签/关系白名单校验）
   ├── 数据转换层（Neo4j 记录 → 前端 graph JSON，含空间字段）
   └── 多库路由层（一园一库，按需聚合）
        │  Bolt（neo4j://127.0.0.1:7687）
        ▼
Neo4j Enterprise（江南古典园林空间知识图谱）
```

- **后端独占 Neo4j 访问**，前端永不直连数据库（tech_stack.md 开发原则 2）。
- 平台对数据库**只读**：不提供任何写接口，保证"不修改原始数据库结构"。
- 前端开发期通过 Vite 代理转发 `/api` 到后端。

## 4. 后端设计（FastAPI）

### 4.1 配置管理（.env）

```
NEO4J_URI=neo4j://127.0.0.1:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password_here
NEO4J_DB_IGNORE=system            # 额外忽略的库名（逗号分隔），空库自动排除
# 三期 LLM（缺省不启用问答模块）
LLM_PROVIDER=   # openai | claude | qwen | deepseek | 空=禁用
LLM_API_KEY=
LLM_MODEL=
```

提供 `.env.example`，真实凭证不入库、不进前端。

### 4.2 多库路由层

- `SHOW DATABASES` 枚举在线标准库，排除 `system` 与节点数为 0 的空库，得到业务库列表；每库取园林根节点名（动态：若存在带 `编号` 属性的园林类节点则取之，否则用库名）作为园林名。
- 查询分两类：**库作用域查询**（空间布局、邻居展开、详情、路径）必须携带 `db` 参数；**跨库聚合查询**（总览、浏览、搜索）遍历业务库执行并带 `db` 字段合并。
- 库列表与 schema 元数据内存缓存（TTL 30s）。

### 4.3 查询安全

1. **用户输入一律参数化**（`$param`），绝不字符串拼接进 Cypher。
2. **动态标签/关系类型**：反引号包裹（`` MATCH (n:`建筑`) ``），且仅允许取自 `db.labels()` / `db.relationshipTypes()` 返回值（白名单校验），杜绝注入。
3. **实体复合主键**：`(db, label, 编号)`，`编号` 在每类标签上有唯一约束（schema.md §8）。
4. **只读执行**：全库仅 MATCH 查询；三期 LLM 生成的 Cypher 另经只读正则白名单校验 + 返回行数限制。
5. **名称回退链**：`名称` → `编号` → 标签名，满足"不假设属性存在"。
6. 跨库节点稳定 ID：`{db}::{label}::{编号}`；关系稳定 ID：`{db}::{elementId(r)}`。

| 方法 | 路径 | 说明 | 阶段 |
|---|---|---|---|
| GET | `/api/health` | 后端与 Neo4j 连通状态 | ① |
| GET | `/api/databases` | 业务库列表（园林名、节点/关系数） | ① |
| GET | `/api/overview` | 总览统计：节点/关系总数、各标签计数、各关系类型计数、各库计数 | ① |

### 4.5 Neo4j → 前端 graph JSON 转换约定

```json
{
  "nodes": [
    {
      "id": "canglangting::建筑::建筑5-1",
      "db": "canglangting",
      "label": "建筑",
      "name": "面水轩",
      "props": { "类型": "轩", "功能": "…", "x": -25.2, "y": -5.3 },
      "degree": 5
    }
  ],
  "links": [
    {
      "id": "canglangting::4:abcd…:1",
      "source": "canglangting::建筑::建筑5-1",
      "target": "canglangting::池沼::池沼2-3",
      "type": "相邻",
      "props": { "相邻类型": "可看", "中介": "水面", "方向": "西偏南", "距离_m": 32.5 }
    }
  ]
}
```

- `props` 原样透传（含空间字段 `x`/`y`、`方向`、`距离_m` 等），前端按需取用，不丢信息。
- 关系保留方向（`source→target`）；`相邻/相接` 为对称双写边，前端提供"合并双向边"开关。

### 5.3 图谱可视化核心设计（GraphCanvas.vue）

#### （1）双模式切换（平台核心交互）

**知识关系模式（默认）**
- ECharts `layout: 'force'` 力导向布局；节点可拖拽、画布可缩放平移（`roam`）。
- 初始数据：`/api/graph/neighbors`（当前园林根节点邻域，深度 1）。
- **双击节点 → `/api/graph/expand` 增量展开**（Bloom 式逐层探索），已加载稳定 ID 去重。

**空间布局模式（园林平面图）**
- 数据：`/api/graph/garden` 一次加载当前园林全部节点与关系。
- `layout: 'none'`，节点坐标取自属性 `x`/`y`：屏幕 y 轴翻转（测绘 y 向北，屏幕 y 向下），按全体节点边界自动缩放适配画布（含内边距），缺失坐标的节点（如园林根节点）回退到质心。
- 该模式还原**园林平面格局**——建筑、水体、山石、花木的实测相对位置一目了然；仍支持节点点击详情、双击展开（同库增量）、缩放平移。

#### （2）空间关系展示

- **边悬浮提示**：知识关系模式与空间布局模式均显示关系类型 + 空间语义属性——`相邻类型`（建筑环线/可看/对景）、`中介`（园路/水面/山径…）、`方向`（中文方位）、`距离_m`；`相接` 边显示 `接触类型`（临水/在山上/在山边）。
- **节点详情面板**：关联节点按关系类型分组，每条关联显示方向（出/入）与关系属性徽标（方向、距离、中介等动态键值）。
- **关系过滤**：工具栏按 `相邻类型`/关系类型值动态生成筛选下拉（值集取自当前已加载链接，无硬编码），过滤边显示。
- **合并双向边开关**：`相邻/相接` 对称双写边可合并显示（仅保留成对边之一）。

#### （3）动态图例与样式

- 节点按标签自动分配 `categories` 调色板（顺序取自 `/api/schema`，新增标签自动顺延）：园林=深红、建筑=蓝、山石=棕、池沼=青、花木=绿……
- 边按关系类型动态映射线型（`属于`=虚线、`相邻`=实线、`相接`=点线）；ECharts 图例控制标签显隐。
- 节点大小 = 关联节点数归一化。

#### （4）交互汇总

单击节点 → 高亮一跳邻居 + 右侧 NodeDetailPanel；双击 → 展开；悬浮 → tooltip；图例/过滤 → 显隐控制；工具栏 → 重置布局、适应画布、模式切换、合并双向边。

### 5.4 游线分析模块（二期）

- 后端 `/api/route`：**数据驱动**——取当前库中全部带 `环线序号` 属性的边（`WHERE r.环线序号 IS NOT NULL`），按序号升序排序，返回站点序列（每段：起点、终点、方向、距离_m、中介、关系类型）、总长与闭环校验结果。
- 已实测沧浪亭数据：14 站闭环（大门 / 入口 → … → 沧浪胜迹坊 → 大门 / 入口），总长 487.7m。
- 前端"游线分析"页：以**空间布局模式**为底图，按序号**逐步动画**高亮游线（起点=入口），侧栏列出行程序列表（序号、建筑名、到下一站的 方向/距离/中介）；无环线数据时优雅降级提示。

## 6. 关键设计决策与依据

| # | 决策 | 依据 |
|---|---|---|

| 3 | 空间模式全库一次加载（`/api/graph/garden`） | 单园 <100 节点，一次加载换取平面图完整性与流畅切换 |
| 4 | 空间关系信息通过 tooltip + 详情面板 + 过滤三层呈现，不硬编码属性名 | 方向/距离/中介等键值原样透传，动态渲染 |
| 5 | 多库路由（一园一库）+ 前端园林切换器 | 实连确认仅 `canglangting` 有数据，其余 21 园为独立 dump；未来若合并单库自动退化 |
| 6 | 只读平台：零写接口 + LLM Cypher 只读白名单 | 约束"不修改原始数据库结构" |
| 7 | 复合主键 `db::label::编号` 作节点稳定 ID | `编号` 仅标签内唯一；跨库跨标签需复合键；也是前端去重合并的键 |
| 8 | 增量展开（`/api/graph/expand`） | Bloom 式逐层探索体验；小数据量下前端 Map 合并开销极低 |
| 9 | 名称回退链 `名称→编号→标签` | 约束"如果节点不存在属性，则仅展示名称/类型/关联关系" |
| 10 | ECharts 为首选（遵循技术文档） | tech_stack.md 指定；数据量小性能足够。若后续需高级图交互可平滑替换 AntV G6（nodes/links 接口一致，后端不变） |
| 11 | 游线分析数据驱动：取全部带 `环线序号` 的边排序（不写死"建筑环线"取值），数据缺失则降级 | 直接利用图谱既有空间语义数据，不新增数据假设；已实测 14 站闭环 487.7m |

## 7. 开发阶段计划

### 第一阶段（必须完成）

1. **Neo4j 连接**：后端 driver、多库路由、业务库枚举（`/api/health`、`/api/databases`）
2. **Schema 读取**：`/api/schema`、`/api/overview`（标签/关系类型/属性键动态采集，前端图例动态生成）
3. **空间布局展示**：`/api/graph/garden` + 前端空间布局模式（x/y 平面图、y 翻转、边界适配）
4. **图谱关系展示**：知识关系模式（力导向）+ 空间关系提示（相邻类型/中介/方向/距离）+ 关系过滤 + 双击增量展开
5. **节点详情**：`/api/entities/detail` + 详情面板（属性表 + 关联分组）
6. 实体浏览（`/api/entities`）与实体搜索（精确优先+模糊）
7. 数据概览页
8. 联调验证（对 `canglangting` 实测双模式）

### 第二阶段（建议完成）

1. **游线分析**：`/api/route` + 游线页（空间底图 + 按环线序号逐步动画，14 站闭环实测数据）
2. 路径查询：`/api/path` + 路径高亮与文字描述
3. **空间条件查询**：`/api/spatial/query`（按 相邻类型/接触类型/中介/方向/最大距离 组合筛选）+ 图谱页空间过滤增强
4. 知识网络分析：`/api/analysis/core-nodes`、`/api/analysis/gardens`、`/api/analysis/spatial`（空间语义分布）+ 分析页
5. 全量园林数据加载后的多库联调

### 第三阶段（扩展）

1. LLM 服务层（Provider 抽象、Cypher 生成、只读校验）
2. 智能问答页面、回答→图谱联动

## 8. 风险与开放问题

| 风险/问题 | 影响 | 应对 |
|---|---|---|
| 其余 21 个 dump 尚未加载到服务器 | 当前仅能演示沧浪亭 | 属运维步骤；平台已按多库设计，加载即可用 |
| 各园 schema 是否一致 | 若某库标签/属性有差异 | 动态 Schema + 名称回退链已兜底；上线前对各库跑 schema 校验 |
| ECharts 力导向在多级展开后的性能与布局抖动 | 大量展开时可能卡顿 | 默认按园作用域（单园 <100 节点）；限制展开深度；备选 G6 |
| `园林` 根节点无 x/y 坐标 | 空间模式缺根节点位置 | 取质心放置；无坐标节点回退 |
| LLM 生成 Cypher 准确性 | 问答答错/超时 | 只读白名单 + 行数限制 + 失败降级提示搜索 |
| Neo4j 弱口令写入 .env | 泄露风险 | .env 不入库；仅本机演示场景 |
