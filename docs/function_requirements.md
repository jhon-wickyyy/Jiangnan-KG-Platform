# 江南古典园林知识图谱可视化平台功能需求文档

# 1. 项目目标

本项目旨在基于已有 Neo4j 江南古典园林知识图谱数据库，开发一个知识图谱可视化交互平台。

平台主要用于：

1. 展示知识图谱整体结构；
2. 浏览数据库中的实体节点；
3. 查询实体之间的关联关系；
4. 通过图形化方式展示知识网络；
5. 支持用户探索园林知识关系；
6. 为后续大语言模型辅助知识查询提供基础。

平台重点不是传统数据库管理，而是利用知识图谱的关系特性，实现园林知识的可视化探索。

------

# 2. 用户角色

## 2.1 普通用户

主要功能：

- 浏览园林知识；
- 搜索实体节点；
- 查看节点关系；
- 探索知识网络。

------

## 2.2 研究人员

主要功能：

- 分析园林实体关联；
- 查询知识路径；
- 探索园林空间和构成关系。

------

# 3. 系统总体功能结构

平台包括以下功能模块：

```
知识图谱可视化平台

│
├── 数据概览模块
│
├── 实体浏览模块
│
├── 实体搜索模块
│
├── 图谱可视化模块
│
├── 关系查询模块
│
├── 知识探索模块
│
└── 智能问答扩展模块
```

------

# 4. 功能详细需求

# 4.1 数据概览模块

## 功能描述

展示当前 Neo4j 知识图谱数据库整体情况。

## 功能内容

## （1）节点数量统计

统计：

- 当前节点总数；
- 不同类型节点数量。

示例：

```
Garden:

30

Building:

xxx

Landscape:

xxx
```

数据来源：

Neo4j 节点统计查询。

------

## （2）关系数量统计

统计：

- 当前关系总数量；
- 不同关系类型数量。

示例：

```
包含关系:

xxx


关联关系:

xxx
```

------

## （3）节点类型展示

展示当前知识图谱包含的实体类别。

示例：

```
Garden

Building

Landscape
```

节点类型应通过 Neo4j 自动读取。

------

# 4.2 实体浏览模块

## 功能描述

按照实体类型浏览知识图谱中的节点。

## 功能要求

用户可以选择不同实体类别：

```
园林

建筑

景观
```

系统展示对应节点列表。

示例：

选择 Garden：

```
网师园

留园

拙政园

寄畅园
```

------

## 展示内容

每个节点展示：

- 节点名称；
- 节点类型；
- 关联节点数量。

------

# 4.3 实体搜索模块

## 功能描述

用户通过关键词搜索知识图谱中的实体。

## 输入

示例：

```
网师园
```

## 输出

返回：

- 匹配节点；
- 节点类型；
- 关联关系。

------

## 搜索要求

支持：

- 精确搜索；
- 模糊搜索；
- 按节点类型过滤。

------

# 4.4 实体详情模块

## 功能描述

展示单个知识节点的信息。

示例：

用户点击：

```
网师园
```

系统展示：

```
节点名称：

网师园


节点类型：

Garden


关联节点：

建筑：

xxx


景观：

xxx
```

------

## 数据来源

信息来自：

Neo4j 节点属性和关系查询。

如果节点不存在属性，则仅展示：

- 节点名称；
- 节点类型；
- 关联关系。

------

# 4.5 知识图谱可视化模块

## 功能描述

将 Neo4j 中的节点和关系转换为可交互图谱。

该模块是平台核心功能。

------

## 输入

用户选择一个节点：

例如：

```
网师园
```

------

## 输出

展示关系网络：

```
        建筑节点


            |

景观节点 —— 网师园 —— 其他节点


            |

        关联节点
```

------

## 交互要求

### （1）节点拖动

用户可以调整节点位置。

### （2）图谱缩放

支持：

- 放大；
- 缩小。

### （3）节点点击

点击节点：

显示节点名称和关系。

### （4）关系展开

点击节点后：

加载新的关联节点。

------

# 4.6 多级知识探索模块

## 功能描述

支持用户从一个实体逐层探索知识网络。

示例：

第一层：

```
网师园
```

展开：

```
网师园

├── 建筑

├── 景观

└── 相关节点
```

继续展开：

```
濯缨水阁

↓

关联节点
```

------

## 目标

实现类似 Neo4j Bloom 的知识探索体验。

------

# 4.7 关系路径查询模块

## 功能描述

查询两个实体之间的关系路径。

------

## 输入

起点：

```
网师园
```

终点：

```
濯缨水阁
```

------

## 输出

展示：

```
网师园

↓

包含

↓

濯缨水阁
```

------

## 实现要求

使用 Neo4j 图查询能力。

支持：

- 最短路径查询；
- 多跳关系查询。

------

# 4.8 知识网络分析模块（扩展）

## 功能描述

对知识图谱结构进行简单分析。

可实现：

## （1）核心节点分析

统计：

连接节点数量最多的实体。

示例：

```
网师园

水体

建筑
```

------

## （2）节点关系统计

分析：

不同园林包含节点数量。

------

# 4.9 大语言模型辅助查询模块（扩展）

## 功能描述

结合大语言模型，实现自然语言查询知识图谱。

------

## 用户输入

示例：

```
网师园有哪些相关建筑？
```

------

## 系统流程

```
用户问题

↓

LLM理解问题

↓

生成Cypher查询

↓

查询Neo4j

↓

返回查询结果

↓

生成自然语言回答
```

------

## 示例

用户：

```
哪些园林包含亭类建筑？
```

系统查询 Neo4j：

返回：

```
网师园

拙政园

留园
```

并生成自然语言回答。

------

# 5. 非功能需求

## 5.1 易用性

平台界面应简洁直观。

用户无需了解 Neo4j 或 Cypher 查询语言即可浏览知识图谱。

------

## 5.2 可扩展性

平台结构应支持后续增加：

- 文献数据；
- 图片数据；
- 测绘数据；
- 多模态知识。

------

## 5.3 数据安全

数据库连接信息：

- 不直接写入代码；
- 使用环境变量管理。

------

# 6. 开发优先级

## 第一阶段（必须完成）

完成：

1. Neo4j 数据库连接；
2. 节点查询；
3. 节点搜索；
4. 图谱可视化；
5. 节点关系展开。

------

## 第二阶段（建议完成）

完成：

1. 数据统计；
2. 路径查询；
3. 实体详情展示。

------

## 第三阶段（扩展）

完成：

1. 大语言模型问答；
2. 智能知识检索；
3. 知识分析。

------

# 7. 开发约束

1. 平台必须基于已有 Neo4j 数据库开发；
2. 不修改原始数据库结构；
3. 不假设数据库存在额外属性；
4. 所有展示内容必须来源于 Neo4j 查询结果；
5. 优先实现知识关系可视化，而非传统信息展示。
